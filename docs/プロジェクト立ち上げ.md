## Cookieセッション
- ブラウザ：セッションIDをCookieに保存
- サーバー：セッションIDとユーザー情報を保存
ログインすると書くリクエストでCookieを送り、サーバーがログインユーザーを確認します。

特徴
- ログアウトや強制無効化が簡単
- サーバー側にセッション保存先が必要
- 複数台構成ではRedisなどを使うことが多い

## JWT
ログインすると、サーバーが署名付きトークンを発行します。
```
JWT
├─ user_id
├─ 有効期限
└─ 署名
```
サーバーは受け取ったJWTの署名と期限を確認します。

特徴
- サーバーにセッションを保存しなくても認証できる
- APIや複数サービスで扱いやすい
- 発行後の強制無効化が少し複雑

## HttpOnly Cookie + JWT
★今回はこれを採用

JWTをブラウザのJavaScriptで管理せず、**HttpOnly Cookieに保存する方式**です。

HttpOnly にすると、Reactから`document.cookie`で読み取れません。  
そのため、JavaScriptからトークンを盗まれるリスクを下げられます。

```
ログイン
→ JWT発行
→ HttpOnly Cookieへ保存
→ 認証MiddlewareがJWTを確認
→ user_idをContextへ設定
```

ライブラリ
```bash
go get github.com/golang-jwt/jwt/v5
```

- フロントエンドの流れ
```
① AuthProviderがアプリ起動時に /api/me を呼ぶ
                          ↓
② ログイン済みなら user にユーザー情報を入れる
   未ログインなら user は null
                          ↓
③ Providerの value で、App以下に共有する
                          ↓
④ ProtectedRouteが user を確認する
                          ↓
⑤ userあり → 画面表示
   userなし → ログイン画面へ移動
```
