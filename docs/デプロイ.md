## 本番環境のマイグレーション

Renderの無料プランでは Pre-Deploy Command を利用できないため、
Start Commandでマイグレーション後にAPIを起動する。

### Build Command
```bash
go build -o bin/api ./cmd/api && go build -o bin/migrate ./cmd/migrate
```

### Start Command
```bash
./bin/migrate && ./bin/api
```

- デプロイ時だけでなく、再起動やスリープ復帰時にも実行されてしまう
- 同じAPIを複数台起動する場合、すべてが同じマイグレーションを実行しようとする
- 一方、Pre-Deploy Commandなら、APIインスタンスの起動とは別にデプロイ処理として1回だけ実行できます。

> Start Command：APIが起動・再起動するたびに実行される
> Pre-Deploy Command：デプロイ時に1回だけ、API起動前に実行される


### React RouterのRewrite設定

MeetingPilotではReact Routerによるクライアントサイドルーティングを使用している。

Renderは通常、リクエストされたURLに対応するファイルを探すため、
`/meetings/123` などへ直接アクセスまたは再読み込みすると404になる。

すべての画面URLで `index.html` を返し、その後React Routerにルーティングさせるため、
RenderのStatic Siteに以下を設定する。

- Source: `/*`
- Destination: `/index.html`
- Action: `Rewrite`

これにより、直接アクセスや再読み込みでもReact Routerの画面が正常に表示される。


# Meeting Pilot：Cookie認証とSameSite設定

## 1. 今回の問題

Meeting Pilotは、フロントエンドとバックエンドが別のRenderサブドメインになっています。

- フロントエンド：`https://meeting-pilot.onrender.com`
- バックエンド：`https://meeting-pilot-api.onrender.com`

ログイン時、バックエンドではJWTを `access_token` というCookieに保存しています。

しかし、Cookieが以下の設定になっていました。

```go
SameSite: http.SameSiteLaxMode,
```
そのため、ChromeがクロスサイトのCookie利用をブロックし、ログイン後の /api/meetings に access_token が送信されない問題が発生しました。

## 2. SameSiteとは？

SameSite は、

> Cookieを別のサイトからのリクエストでも使用してよいか

を決めるセキュリティ設定です。

主な設定は3種類あります。

設定|意味
-- | --
Strict | 別サイトからのCookie利用をかなり厳しく制限
Lax | 制限はあるが、通常のサイト遷移などは許可
None | クロスサイトでもCookieを使用可能

## 3. SameSite=Laxとは？
```go
SameSite: http.SameSiteLaxMode,
```
は、

>基本的には同じサイト内でCookieを使い、クロスサイト通信ではCookieの利用を制限する

という設定です。

今回の構成では、
```
https://meeting-pilot.onrender.com
        ↓
https://meeting-pilot-api.onrender.com
```
という通信になります。

ブラウザから見るとクロスサイト通信として扱われるため、SameSite=Lax では今回のCookie認証に問題が発生しました。

ChromeのDevToolsにも、

```
SameSite=Lax属性は指定されていたものの
トップレベルナビゲーションへのレスポンスではない
クロスサイトレスポンスが送信元でした。
```
という警告が表示されました。

## 4. SameSite=Noneとは？
```go
SameSite: http.SameSiteNoneMode,
```
にすると、

> クロスサイトの通信でもCookieを使用してよい

という設定になります。

ただし、`SameSite=None` を使う場合は `Secure=true` が必要です。

```go
SameSite: http.SameSiteNoneMode,
Secure:   true,
```

これは、

> HTTPS通信の場合のみ、クロスサイトでもCookieを送信する

という意味です。

Renderの本番環境はHTTPSなので、この設定が適しています。

## 5. 開発環境と本番環境

開発環境：
```
Frontend: http://localhost:5173
Backend:  http://localhost:8080
```

本番環境：
```
Frontend: https://meeting-pilot.onrender.com
Backend:  https://meeting-pilot-api.onrender.com
```
そのため、環境によってCookie設定を切り替える方法がおすすめです。

## 6. おすすめの実装

現在のCookie設定を以下のようにします。
```
sameSite := http.SameSiteLaxMode

if cookieSecure {
    sameSite = http.SameSiteNoneMode
}

c.SetCookie(&http.Cookie{
    Name:     "access_token",
    Value:    token,
    Path:     "/",
    HttpOnly: true,
    Secure:   cookieSecure,
    SameSite: sameSite,
    MaxAge:   60 * 60,
})
```
